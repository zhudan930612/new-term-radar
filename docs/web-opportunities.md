# Web 网站需求机会工作流

目标：持续发现真实用户任务，再判断是否适合做一个有边界的 Web 网站。单条具体问题值得保留，但不等于可以立项；允许没有新增机会。

## 每天实际怎样运行

可配置 Codex 自动任务每日运行（例如台北时间 10:00）。电脑和 Codex 需在运行，并在本机提供 AIsa 凭据和 GitHub 登录；调度与凭据不随仓库分发。

1. **任务入口**：轮换 4 次 X 任务检索（最近 30 天），有历史种子时其中 1 次改为定向补证；免费检索 GitHub 跨仓库公开 Issues 和 HN 讨论。启用 `research.enabled` 后，加入 Reddit 求助原文，以及围绕历史待补证任务或配置的探索任务词检索的 Reddit 痛点、YouTube 教程评论和 Chrome 扩展评论。Chrome 评论需要可选的 GoAnyAPI Key，未配置时明确显示缺口。所有原文进入同一语义审核，不先用点赞、星数、搜索量或旧模型结论过滤。记录查询、窗口、返回量、失败、未知作者与未读范围；教程本身和产品介绍不能代替真实用户请求。
2. **技术补充**：最多检查已有候选池中的 2 个产品。默认不每日付费扫描官方账号/新产品名字，名称仅为补充背景。旧名称发现功能仍保留，可另行运行；名字池 14 天、7 天复查，不作为需求入口。
3. **模型预处理**：Qwen 逐条分类、抽取用户/任务/场景/痛点/输出/限制/替代方案/频率/成本。缺少的事实填未知。第二轮盲读全部来源，不只复查正例。模型选原文段落编号，程序还原逐字引文。异常来源保留，不能当负例；新增入口同样接受后续 Codex 全源复核。
4. **跨日需求池**：具体任务写入 `state/demand-ledger.json`。单用户也保留；同 URL 重复不算第二份证据，同作者不算第二个人。保留 60 天活跃窗口及完整历史；不同任务不能只因话题接近就合并。错误合并可恢复原任务。新证据、失败与到期（7 天）任务才重审，模型每轮最多审 18 个；容量不足明确显示。历史失败来源每天最多补处理 24 条。
5. **Codex 最终语义审核**：自动任务逐条读原文，审核所有正例、负例、模糊项及任务去向，纠正营销文归因、任务混淆和模型错误。使用下方受控导入，不额外调用 AIsa。此步骤完成前 `awaiting_audit` 或 `incomplete` 都不能发布“没有机会”。模型通过格式检查不代表语义正确。
6. **晋级**：至少两条可辨别的独立账号请求、同一个窄任务、原文一致且 Web 方案可行，才进入最多 3 个“值得深入验证”。不同账号不保证真人身份独立，后续必须看上下文。只发布未报告过的证据版本；历史方向留在需求池，新证据才重新上榜。名称热度、模型分数不能证明市场。
7. **先验证原文和搜索意图**：仅对入选方向读取原始上下文与美国英文搜索结果，核对同一任务、独立性、同名歧义，并看最多两种现有替代方案。原文证据被推翻会撤回推荐；搜索词不对只标待改词。具体命令见 [验证交接](web-automation.md)。
8. **竞争与营收背景**：执行 `research-opportunities`，只处理已完成全源语义审核、原文/独立性与搜索意图均通过且未撤回的最多 3 个方向。保存美国 Google 首页原始结果和关键词难度证据；有 GoAnyAPI Key 时补充域名评分、广告主和标题竞争。缺 Key、失败或空结果都不能解释为低竞争。TrustMRR 每轮读取一次，缺 Key 则标记 unavailable；只有产品域名与搜索结果域名精确重合才列为背景候选，仍不证明同一任务或该机会能够盈利。原始证据、阶段状态和费用单独保留，不更改需求审核结论。
9. **再查 Google Trends**：仅对原文/搜索意图确认的短语查美国近 90 天、近 365 天；最多六页，免费、失败不切付费。竞争/营收数据缺口不会被趋势结果补成已验证事实。低搜索热度不否定小众任务；0–100 不是搜索次数。见 [Google Trends](google-trends.md)。
10. **后续真实验证**：获得用户任务样例，复现现有替代流程，测质量、耗时和每次处理成本；找到可接触的目标用户渠道，再做一个功能的实验。付费意愿、获客、留存和盈利目前都不是日报已验证事实。自动充值、接触他人、开发、发布以及已配置流程之外的额外研究需另有用户授权。

## 日报如何读

- 完整且无新增方向：**本轮样本中没有新增达到深入验证门槛的 Web 网站机会。** 同时列待补证种子及原因，不能说市场没有需求。
- 单用户任务：保留待补证；下一轮优先查同一任务的第二条证据，7 天内不重复审未变化任务。
- 非 Web 任务：保存原始需求，说明约束，不擅自改成“用户愿意上传文件”。
- 来源失败、空样本、历史修复积压或语义复核未完成：**本轮未完成**。保留有效部分及具体缺口。
- 入选：仅值得验证。原文/搜索意图、Trends、竞争/获客/商业验证的状态分别展示。

## 运行与恢复

在仓库根目录、已配置本机凭据的环境中运行：

```powershell
python -m radar opportunities --config config.json --state state
```

单独执行 Python/PowerShell 只到模型预处理和审核计划，不能替代 Codex 语义复核及浏览器访问。`--from-report` 仅复用当天旧采集快照。同日重复运行只读已有结果，不重新采集或计费。日报 JSON 权威文件为 `state/web-opportunities/YYYY-MM-DD/result.json`，旁边 `result.md` 为报告副本。

兼容上游 0.4.0：保留 `asks`、`tutorials`、`pains`、`revenue` 和搜索首页竞争能力。Web 日报按上述阶段接入原始需求与后续研究，不继承旧版的热度/搜索量筛选门槛或“有营收即证明需求”的推断。独立 `keywords`、`pains` 及旧版付费日报仍可使用，但不受 Web 日报请求账本保护，不能当作离线测试执行。

已有免费启动方式继续有效：`daily --skip x,newsites,review,judge,usecases`（可追加其他跳过项）会同时跳过上游新增的 `asks`、`tutorials`、`revenue`。完整免费跳过集合优先于 `--asks`、`--revenue` 强制运行标志；免费结果仍是原版线索报告，不能视作已完成 Web 需求审核。

质量优先配置使用 `opportunities.budget_usd: null`，不设旧的每轮 $0.20 金额上限；仍保留有界采样、实时询价、费用预留、请求账本、缓存和余额保护，不会自动充值。金额上限设置为正数时仍按配置执行。AIsa 每个付费请求发出前记账，可用余额扣除 $0.01 余量不足时停止。最终账单可能与报价不同；阶段请求账本与前后余额差分别报告，账户并发调用不能全部归因本轮。GoAnyAPI 和 TrustMRR 不包含在 AIsa 余额/费用中，也不受其余额保护，单独显示来源及费用缺口。

AIsa 已知、费用明确的单来源失败仅隔离该请求，其他来源可以继续。仅允许列表中的只读数据请求可有限重试：完整回包必须逐项匹配请求，并同时明确失败、上游临时错误、可重试及数值型零费用；最多 3 次总尝试，历史失败计入次数，间隔退避且每次重新询价。每次请求、回包、预留和实际费用分别留档，成功响应仍按原请求指纹复用。费用未知、超时、中断、回包无法归属或账户/鉴权问题继续全局保护，模型与 Web 流程内 GoAnyAPI 不自动重试。

询价使用 AIsa `batch_quote`，逐项校验请求归属、成功状态及 USD 费用；有明确上界时按上界预留，仅有估算时不宣称金额硬上限。2026-10-16 核验的自动重试范围为 X 查询与 Reddit 查询这三个只读、幂等 GET 操作；Google/YouTube 等 POST 数据接口仍可采集，但供应商标为非幂等，不能自动重试。

不能删除请求账本、结果或锁来绕过保护。同日阶段已经开始时，不因 partial/incomplete 自动重跑整份日报；诊断后恢复未完成范围，保留恢复前快照、原查询范围和费用归属。Codex 审核可根据已保存来源修复模型分析错误，不能掩盖未采集、空样本及范围积压。

配置：

```json
"demands": {"enabled": true, "free_sources": true, "technology_discovery": false},
"research": {"enabled": true, "reddit_queries_per_day": 4, "pain_tasks_per_day": 3,
  "videos_per_task": 2, "chrome_extensions_per_task": 2, "chrome_review_pages": 1,
  "seed_task_phrases": ["batch document conversion", "invoice data extraction", "subtitle editing"]},
"opportunities": {"enabled": true, "model": "qwen3.7-flash", "budget_usd": null,
  "candidates_per_day": 2, "problem_queries_per_day": 4, "recheck_days": 7}
```

以上为配置片段。`config.example.json` 提供启用研究、取消旧金额上限的示例；代码缺省 `research.enabled=false` 保持已有配置兼容，已有本机配置应合并所需字段，不能用示例整份覆盖。探索任务词只是明确的采样起点，不是已经发现的需求。

源数据、分类修订、审核输入、API 请求账本和错误均保留在忽略的本地状态目录。API 日志不保存认证头或 Key。发现重试锁需先诊断，不能为了成功状态删除记录；这些运行数据、账户信息和真实样本不提交到 Git。

YouTube 评论的抓取日不等于发表日。保留供应商的相对发表时间、估算时间、作者页面和视频信息；只有 handle 页面而没有可核验账号 ID 时，身份仍为未知，共享视频 URL 不能充当多名独立用户的证据。明确的零评论采样与接口故障分别记录，零评论查询仍可能收费；解释已保存回包不等于再次调用接口。

## 已知覆盖限制

目前是公开 X、GitHub、HN、Reddit 及教程/扩展评论的有限采样，仍偏英语与技术人群。任务词、窗口、每页/每任务数量限制会漏掉其他人群；YouTube 仅取一页顶层评论，未读回复和供应商原文完整性保留未知。显示名不能当可靠账号；Chrome 共用扩展 URL 的评论不能仅凭多条记录凑独立证据。没有历史待补证任务时使用明确配置的探索词，覆盖面受这些词约束。

美国只是搜索验证市场，不能据此推断发帖者所在国家。TrustMRR 是有限且经过筛选的产品样本，未匹配不是不存在付费需求；搜索首页、KD/DR 和广告也不验证获客成本或盈利。新增入口的离线测试验证门禁、数据结构与失败处理，不代表已经实测了付费供应商的全部当前行为；真实来源回放与真实市场验证应另行说明依据。
